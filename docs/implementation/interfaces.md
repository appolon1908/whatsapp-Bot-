# Bot implementation contracts

User authorized implementation on 2026-10-27 after the architecture/source review. Scope is this repository first. The accepted baseline is `docs/architecture/commerce-platform.md` (WhatsApp PR23, SHA 9f37e1c57a34d575b21729d17efa12aa139798b0). Implementation choices below are engineering decisions, not additional user promises.

## Stack and boundaries

Python >=3.12; FastAPI; synchronous SQLAlchemy 2.0; psycopg3; Alembic; PyJWT with RS256 and configured issuer/audience/JWKS; PostgreSQL >=16. Money is integer minor units. Pilot currencies USD and DOP. UTC stored timestamps, IANA business timezone. All service methods run inside the caller's transaction and MUST NOT commit. API commits before successful responses; worker commits durable state before acknowledging work.

Package `whatsapp_bot`. Model schema `commerce`. UUID primary keys, timezone-aware datetimes, JSONB structured fields. Business tables have `tenant_id`, `UNIQUE(tenant_id,id)`, composite tenant foreign keys, ENABLE and FORCE RLS. `Business.id` is its tenant ID. Tables owned by NOLOGIN `codestra_whatsapp_owner`; runtime `codestra_whatsapp_app` is NOSUPERUSER NOBYPASSRLS and cannot inherit or SET ROLE to owner or migrator. Runtime has no DDL/TRUNCATE. The separate `codestra_whatsapp_migrator` login is NOINHERIT/NOBYPASSRLS with SET-only owner membership; normal operator commands authenticate as that login and explicitly activate the owner within the transaction. The bootstrap administrator is limited to provisioning and a validated legacy version-table ownership handoff. Database names are restricted to `codestra_whatsapp_commerce` or names with that prefix for isolated tests. No controller database modifications.

## Persistence interfaces (Task 1 owns)

`db.py`: `make_engine(url: str) -> Engine`; `tenant_session(engine, tenant_id: UUID)` contextmanager creates a Session and a transaction and calls parameterized transaction-local `set_config('app.tenant_id', str(tenant_id), true)`; never leak tenant state on pooled reuse; commit on normal exit and rollback on error. `lookup_channel(engine, provider: str, account_id: str, phone_number_id: str) -> tuple[UUID, UUID] | None` uses a narrow SECURITY DEFINER SQL function returning active tenant/channel IDs only, after caller authenticates ingress. The function has fixed search_path, no dynamic SQL, PUBLIC execute revoked; only the trusted schema owner has the special SELECT policy on channels. No global read grants on customer/business data. `assert_runtime_role(engine)` requires both session/effective identities to be the app, rejects elevated attributes, explicit memberships or database/schema/object ownership, and verifies the exact database target.

`models.py` exports Base and these ORM classes (snake_case database columns):

- Business: id, name, currency, timezone, active, tax_bps, settings(JSONB), created_at. Settings can hold business opening hours. Tax rate must be explicitly supplied on onboarding.
- Membership: id, tenant_id, subject, role(owner/supervisor/agent/fulfillment), active; unique tenant+subject.
- Channel: id, tenant_id, provider(meta/evolution), account_id, phone_number_id, active, policy_campaign_id(nullable). Unique provider+account+phone globally. No provider tokens.
- Product: id, tenant_id, sku, name, description, price_minor, currency, stock_on_hand, stock_reserved, version, active, image_url(nullable); unique tenant+sku; nonnegative stock and reserved <= on_hand.
- DeliveryZone: id, tenant_id, code, name, fee_minor, minimum_minor, active; unique tenant+code.
- Conversation: id, tenant_id, channel_id, customer_ref, language(en/es), mode(bot/human), assigned_to(nullable subject), version, consent_status(unknown/opted_in/opted_out), consent_at(nullable), consent_evidence(nullable), bot_state(JSONB), created_at; unique tenant+channel+customer.
- Message: id, tenant_id, conversation_id, provider_message_id(nullable), direction(inbound/outbound), text, status, created_at. Provider IDs scoped to channel/conversation, never global customer identity.
- Cart: id, tenant_id, conversation_id, version, status(active/ordered); one active cart per conversation via partial unique index.
- CartItem: id, tenant_id, cart_id, product_id, quantity; unique tenant+cart+product.
- Quote: id, tenant_id, cart_id, conversation_id, cart_version, currency, subtotal_minor, delivery_minor, tax_minor, total_minor, address, fulfillment(pickup/delivery), zone_code(nullable), expires_at, created_at.
- QuoteItem: id, tenant_id, quote_id, product_id, product_version, sku, name, quantity, unit_price_minor, subtotal_minor.
- Order: id, tenant_id, quote_id, conversation_id, idempotency_key, status(submitted/accepted/preparing/out_for_delivery/delivered/ready_for_pickup/collected/rejected/cancelled), payment_status(unpaid/paid_externally/refunded_externally), currency, subtotal_minor, delivery_minor, tax_minor, total_minor, address, fulfillment, reservation_expires_at, created_at. Unique tenant+quote and tenant+idempotency_key.
- OrderItem: id, tenant_id, order_id, product_id, sku, name, quantity, unit_price_minor, subtotal_minor.
- InboundEvent: id, tenant_id, channel_id, event_id, payload_hash, payload(JSONB), state(pending/done/dead), attempts, next_attempt_at, last_error(nullable safe code), created_at. Unique tenant+channel+event_id.
- OutboxEvent: id, tenant_id, conversation_id, conversation_version, event_key, kind, payload(JSONB), state(pending/done/sent/cancelled/dead), attempts, next_attempt_at, last_error(nullable safe code), command_id(UUID stable), policy_operation_id(nullable), created_at. Unique tenant+event_key.
- AuditEvent: id, tenant_id, actor, action, object_type, object_id(nullable UUID), details(JSONB), created_at. Avoid secrets and unnecessary full message/address copies in audit.

`errors.py`: `CommerceError(code: str, message: str, status: int = 409)`; stable public code/status and safe message.

`commerce.py`: `CommerceService(session: Session, tenant_id: UUID, actor: str)` with JSON-compatible dict return values (IDs strings, timestamps ISO):

- `create_product(data: dict)`, `update_product(product_id: UUID, data: dict)`, `list_products(limit=100, offset=0)`, `get_product(product_id)`, `adjust_stock(product_id, delta: int)`.
- `create_zone(data)`, `list_zones()`, `update_zone(zone_id, data)`.
- `create_conversation(channel_id: UUID, customer_ref: str, language='en')`, `get_conversation(conversation_id)`, `list_conversations(limit=100, offset=0)`, `set_mode(conversation_id, mode: str, assigned_to: str|None=None)`, `set_consent(conversation_id, status: str, evidence: str)`.
- `get_cart(conversation_id)`, `set_cart_item(conversation_id, product_id: UUID, quantity: int)` (zero removes; 1..100 otherwise), `quote_cart(conversation_id, fulfillment='pickup', zone_code=None, address='')` (15-minute quote TTL, correct round-half-up tax in integer math, validate configured business hours and active zone/minimum), `confirm_quote(quote_id: UUID, idempotency_key: str)`.
- `get_order(order_id)`, `list_orders(limit=100, offset=0)`, `transition_order(order_id, target: str)`, `mark_payment(order_id, status: str, reference: str)`, `expire_reservations(now=None) -> int`.

Service raises CommerceError for invalid inputs/missing objects/conflicts. No global ID lookup then tenant check: tenant scoping/RLS must apply to every query. Actor string is an already-authorized subject or `worker`; service does not replace API RBAC. Lock affected conversation/cart/quote/product/order rows consistently; sort product locks. Recheck product active/version/price/currency, cart version and quote expiry at confirmation. Exactly one order per quote even with different keys. A key reused for a different quote is a conflict. Atomically reserve stock, create order, immutable line/total snapshots, audit and `order.submitted` OutboxEvent with `{order_id}` payload. On order transitions emit `order.updated` with `{order_id,status}`. Worker turns these into replies. Submitted unaccepted reservations expire after 30 minutes; acceptance prevents automatic expiry. Cancellation/rejection releases once; delivered/collected consumes once. Invalid transitions fail. Handover increments conversation.version and cancels pending message.reply records. Cart edits invalidate old quotes. Conversation IDs/ownership verified before a worker acts on an explicit quote/order identifier.

Provisioning interface: `provision.py` exposes `provision_database(admin_url, database_name, app_password, *, migrator_password)` for an explicit bootstrap/test invocation only, and `bootstrap_business(migrator_url, name, currency, timezone, owner_subject, tax_bps)` returning JSON business. Provisioning is idempotent/non-destructive, refuses unrelated DB names and unsafe existing dedicated-role grants, never runs at API startup, and does not change unrelated databases or global host authentication rules. Migration/onboarding/registration use the authenticated named migrator and activate the owner explicitly. Both logins need reviewed HBA connection restrictions and effective-access tests; PostgreSQL PUBLIC CONNECT must be documented honestly.

## Messaging interfaces (Task 2 owns)

`messaging.py`: `IngressService(engine, secret: str)` exposes `accept(raw_body: bytes, timestamp: str, signature: str) -> dict`. HMAC SHA256 is over `timestamp + b'.' + raw_body`, header value `sha256=<hex>`, max clock skew 300 seconds; secrets shorter than 32 bytes disable ingress; constant-time compare, 1MiB bound and strict JSON object validation. Resolve tenant exclusively via signed provider/account/phone matching lookup_channel; reject unknown/inactive mapping. Required event fields: event_id (1..200), provider(meta/evolution), provider_account_id, phone_number_id, provider_message_id, event_type(message.received/message.delivery.updated), occurred_at (aware RFC3339), payload_schema_version=1, trace_id; customer message includes customer_ref and text <=4096. Delivery event contains status(sent/delivered/read/failed). Reject unexpected tenant_id/role fields. Store event in one durable transaction before returning accepted. Exact duplicates accepted idempotently; same event_id changed content rejected. Occurrence timestamps and delivery states are handled explicitly, not blind overwrites.

`bot.py`: `process_inbound(session, tenant_id, event: InboundEvent) -> None`; deterministic Spanish/English commands: START/INICIAR (explicit opt-in), STOP/PARAR (opt-out), MENU/CATALOG/CATALOGO, ADD/AGREGAR <SKU> <qty>, REMOVE/QUITAR <SKU>, CART/CARRITO, CHECKOUT/FINALIZAR PICKUP/RECOGIDA or DELIVERY/ENTREGA <zone> <address>, CONFIRM/CONFIRMAR <quote UUID>, ORDER/PEDIDO <order UUID>, HUMAN/HUMANO. Unknown/ambiguous messages offer concise help or human takeover. Customer cannot choose tenant, change prices, mark payment, or resume human mode. Explicit quote/order IDs must belong to the same conversation. Commands serialize by locking conversation; dedup comes from inbox. Human mode records inbound text but suppresses bot replies. START is consent evidence, ordinary incoming text does not fabricate opt-in. Order acknowledgement is generated from the committed order.submitted event, not duplicated by bot confirmation.

`worker.py`: `Worker(engine, *, tenant_ids: list[UUID], policy_client=None, outbound_enabled=False, max_attempts=8)`; `tick() -> dict` processes bounded per-tenant batches (round robin; rows FOR UPDATE SKIP LOCKED), inbox, order business events, message replies, and reservation expiry. Single transaction per inbox item including bot state/message/outbox. On failure rollback and record safe error/attempt with exponential bounded delay; dead-letter after max_attempts. Business events create one stable-key reply then state=done. `message.reply` payload captures deterministic text and stable IDs. Dispatcher checks current channel readiness/campaign ID, current consent, mode and conversation version under a conversation lock immediately before submission; hold lock across bounded HTTP submission to serialize handover. Never send when outbound_enabled=False; leave message pending with safe readiness reason. Retry preserves command_id and idempotency_key. Cancel stale/human/opted-out replies. Track operation ID; successful messages state=sent; delivery status is separate from order state. No sender secrets in DB/payload/logs. Worker uses explicitly configured tenant IDs, no global customer reads.

`policy.py`: `PolicyClient(base_url, bearer_token, timeout=5)`; `send(payload: dict) -> dict` POSTs ONLY `/platform/v1/whatsapp/messages`, checks HTTPS unless explicit local-development allowance, no redirects, bounded timeout, validates operation/command acknowledgement and emits safe transient/permanent errors. Payload includes tenant_id, requested_by, command_id, correlation_id, idempotency_key, recipient, instance_id/phone binding, message{text,type}, verified consent flags, campaign_id, and business_context. Existing policy source currently omits campaign_id downstream: document integration blocker, never call provider or invent approval/consent to bypass it. No actual network effects in tests: fake HTTP transport only at external boundary.

## API/config/auth interfaces (root owns Task 3)

Settings fields include database_url (secret), expected_database_name, jwt_issuer, jwt_audience, jwks_url or jwt_public_key (RS256 only), ingress_secret(secret), policy_base_url, policy_bearer_token(secret), outbound_enabled=False, worker_tenant_ids, environment(local/test/production). No unsigned/header-only auth/dev bypass. `create_app(settings, engine=None, token_verifier=None)` dependency injection only; injected verifier is for in-process tests, never environment enabled. Missing identity config fails closed (503), invalid token 401; authenticated nonmember/role mismatch 403; UUID object not visible 404.

All staff business endpoints `/commerce/v1/...` require bearer JWT and `X-Business-ID` validated against active persisted Membership for verified sub. Header chooses among authorized memberships; it cannot itself authorize a tenant. Owner/supervisor catalog/settings/orders; owner membership/channel management; agent only assigned conversations and their orders; fulfillment order fulfillment with address, not message/catalog administration. Read catalog all members. Conversation/message endpoints exclude fulfillment. Explicit payment recording only owner/supervisor and audit reference required. Fulfillment cannot reject/cancel or mark payments.

Routes: healthz, readyz (503 if DB/role/schema/identity or ingress unready; disabled outbound is a reported safe mode); products CRUD/stock; delivery-zones CRUD; conversations/list/history/handover/resume/assignment/consent; cart read/items; quotes create; orders create/list/get/transitions/payment; business settings; memberships; channels; authenticated safe queue status/dead-letter replay preserving idempotency. Internal ingress `/internal/v1/whatsapp/events` authenticates HMAC independently, no staff-header identity. Bound payloads/list sizes. API logs correlation IDs, not tokens/addresses/messages/SQL params. No automatic create_all/migrations at runtime.

CLI commands migrate, provision, onboard-business, create-channel, worker --once, API. Privileged commands require explicit owner/admin DSN and target checks. Do not deploy into CRM as part of this implementation.

## Verification contracts

Tests use actual PostgreSQL with distinct owner/app roles, never SQLite. Shared fixtures will be in tests/conftest.py (Task1 owns): `engine` runtime Engine, `admin_engine` owner/admin test Engine, `tenant_a`, `tenant_b` UUIDs, `tenant_session` callable (tenant UUID -> contextmanager), `business_factory` for deterministic tenant setup. Initial ownership/data is seeded by admin fixture; each test cleans only task's test DB. Environment TEST_DATABASE_ADMIN_URL points to throwaway local/CI server and COMMERCE_TEST_DATABASE_NAME uses allowed prefix. Assert no-context reads empty/writes fail, cross-tenant FK/RLS writes fail, invalid JWT/issuer/audience/algorithm/expiry denied, API role checks, quote expiry/repricing/currency, concurrent last-stock checkout, duplicate webhooks/confirmations, rollback before commit, human takeover cancels pending replies, opted-out no sends, retry stable IDs, restore into isolated DB with pending work. Every task adds meaningful regression tests before implementation and reports red/green evidence.
